# BOOT.md — ParametricCombustionModel.Telemetry

## Purpose

Телеметрия прогона: реестр приборов, измеряющий контекст задачи, показания
сборщика мусора. Всё, что печатает раздел производительности отчёта, собрано
здесь.

## Invariants

- `PerformanceMeter` — реестр, а не измеритель: он заводит приборы и держит
  их список, чтобы отчёт мог их перечислить. Прибор, созданный мимо реестра,
  в отчёт не попадёт.
- Измеритель полного времени один на реестр и создаётся лениво при первом
  запросе. Секундомер стартует в конструкторе однократного измерителя,
  поэтому «первый запрос» и есть начало отсчёта.
- Телеметрия на горячем пути и потому распределена по воркерам: один
  накапливающий измеритель на воркер, статистика по Уэлфорду без хранения
  выборки. Общий измеритель молча испортит числа.
- ⚠ Реестр сам **не потокобезопасен**: `CreateExecutionFrameMeasurer`
  добавляет в обычный `List`. Приборы заводятся при построении матрицы
  контекстов, до старта воркеров, и только поэтому гонки нет.
- Сборка ссылается на [Optimization](../ParametricCombustionModel.Optimization/API.md),
  а не наоборот: измеряющий контекст обязан наследовать измеряемый. Обратной
  ссылки быть не может, иначе цикл сборок.

## Dependencies

- [Optimization](../ParametricCombustionModel.Optimization/API.md) — базовый
  контекст задачи, посетители, оценщики штрафов;
- транзитом через него — [Computation](../ParametricCombustionModel.Computation/API.md).

## Constraints

Унаследованы от [корня дерева](../../BOOT.md). Дополнительно: измерение не
имеет права менять числа расчёта — обёртка прозрачна по результату.
