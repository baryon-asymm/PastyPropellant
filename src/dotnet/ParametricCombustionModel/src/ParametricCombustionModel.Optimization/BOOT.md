# BOOT.md — ParametricCombustionModel.Optimization

## Purpose

Поиск параметров модели: определение «насколько хорошо модель описывает
измерения», физические ограничения в виде штрафов, мост к библиотеке
дифференциальной эволюции и результат в виде, пригодном для отчёта. Сборка —
библиотека; запускает поиск хост консоли, лежащий вне этого дерева.

## Invariants

- Целевая функция определена **ровно один раз** и одинаково для поиска и для
  отчёта: средняя по топливам среднеквадратичная относительная невязка плюс
  сумма штрафов.
- **Параллельность выражена формой матрицы задач `[воркер, группа]`.** Каждый
  воркер владеет своими контекстами; контексты мутируются при решении, поэтому
  разделение их между потоками портит результат.
- Групповая формулировка — 32 параметра: 11 общих и три блока по 7. `Bas_2`,
  `Bas_3` и `Bas_4` всегда оптимизируются как одна группа с общими
  параметрами композиции, и это несущая причина самой групповой постановки.
- Финальная оценка сошедшегося решения и прямой расчёт одного вектора идут
  одним публичным методом. Отчёт и повтор обязаны совпадать бит в бит.
- Сборка ссылается на [Computation](../ParametricCombustionModel.Computation/API.md)
  и на внешнюю `PastyPropellant.Core`, но **ничего не знает** об отчётах,
  графиках и хосте.
- Журналирование — только публикацией события в статическую шину; иных
  интерфейсов журналирования в дереве нет и заводить их запрещено.

## Dependencies

- [Computation](../ParametricCombustionModel.Computation/API.md) — модель, чьи
  параметры ищутся;
- [Core](../ParametricCombustionModel.Core/API.md) — описание топлива, откуда
  берутся измеренные коэффициенты закона Вьеля.

Вне дерева: `DotNetDifferentialEvolution` 5.1.0, `DotNetNelderMead` 1.0.0,
`DotNetNelderMead.DifferentialEvolution` 1.0.0 (двоично несовместим, см.
[Settings](./Settings/BOOT.md)) и сборка `PastyPropellant.Core`.

## Constraints

Унаследованы от [корня дерева](../../BOOT.md). Дополнительно: горячий путь.
Оценка вызывается на каждую особь каждого поколения многочасового запуска,
поэтому ярус `ByDoubles` здесь не оптимизация, а условие осуществимости.

## Acceptance criteria

- [x] Контракты внешней библиотеки, на которые опирается сборка, закреплены
      тестами: индекс воркера, воспроизводимость по зерну, поведение
      начальной популяции, форматирование величин UnitsNet (2026-09-05, узел
      [Optimization.Tests](../../tests/ParametricCombustionModel.Optimization.Tests/BOOT.md)).
- [ ] Ни один тест не проверяет значения штрафов и определение целевой
      функции напрямую. Косвенно их держат тесты отчёта, которые пересчитывают
      те же числа.
- [ ] Внутри сборки есть **цикл между узлами `Models` и `Interfaces`**:
      `Interfaces` называет задачи оптимизации в своих сигнатурах, а `Models`
      реализует объявленные там интерфейсы. Дерево это описывает, но не
      оправдывает; развязка — предмет проектной сессии.

- Не добавлять второй путь финальной оценки.
- Не включать мемётическую полировку до появления адаптера против ДЭ 5.x.
