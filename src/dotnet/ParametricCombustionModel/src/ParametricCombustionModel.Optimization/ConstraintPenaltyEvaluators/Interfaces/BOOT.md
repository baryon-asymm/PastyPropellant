# BOOT.md — Interfaces

## Purpose

Контракт оценщика штрафа: по посчитанному контексту задачи вернуть добавку к
целевой функции. Уровень существует, чтобы оптимизатор держал штрафы
однородным списком и не знал, сколько их и какие они.

## Invariants

- Метод объявлен **дважды**, по одному на ярус контекста
  (`ProblemContextByUnits` и `ProblemContextByDoubles`). Тот же инвариант
  пары, что и во всём дереве: штраф, посчитанный в поиске, обязан совпасть со
  штрафом, напечатанным в отчёте.
- Контекст на входе — **уже посчитанный**: оценщик читает результат решения и
  ничего не решает сам.
- Возврат — `double`, не «нарушено / не нарушено». Величина штрафа несёт
  степень нарушения, и это то, по чему поиск чувствует направление.
