# BOOT.md — KnownParams

## Purpose

Вход расчёта: всё, что известно до решения одной точки. Три разных по природе
вещи собраны здесь потому, что все они попадают в контекст задачи, — вектор
искомых параметров решателя (18 на композицию и 32 на группу), свойства
топлива и пламён при данном давлении, и постоянные модели, выбираемые на
запуск.

## Invariants

- **Три разных статуса чисел, и их нельзя путать.** `CombustionSolverParams…`
  — то, что ищет оптимизатор. `PropellantParams…`, `KineticFlameParams…`,
  `DiffusionFlameParams…`, `MetalCombustionParams…`, `SkeletonLayerParams…` —
  то, что пришло из данных. `ModelConstants` и
  `SkeletonSurfaceFractionSettings` — то, что выбрано на запуск и обязано
  попасть в отчёт.
- Раскладка группового вектора **32 = 11 общих + 3 × 7**: слоты `[0..10]`
  общие, `[11..17]` — группа `Bas_2 + Bas_3 + Bas_4` (индекс 0), `[18..24]` —
  `Bas_1` (индекс 1), `[25..31]` — `Bas_0` (индекс 2). `ToCompositionVector`
  собирает из этого 18-элементный вектор композиции. Тот же порядок обязаны
  соблюдать все, кто нарезает или отчитывается по этому вектору.
- `FromVector` есть в обоих ярусах и обязан читать одну и ту же раскладку:
  расхождение между ними означает, что размерный отчёт описывает не тот
  вектор, который считал поиск.
- Векторы параметров — `readonly ref struct`: они не могут утечь в поле, в
  замыкание или в задачу, и это удерживает их на стеке воркера.
- `ModelConstants.Default` **тождественно воспроизводит исторические
  «зашитые» значения** (1300 К, коэффициент контакта 1.0, полиномиальное
  замыкание, вилка 600–900 К). Ненастроенный запуск обязан считать то же, что
  считал всегда.
- `ModelConstants.Validate` бросает, а не исправляет: неположительная или
  бесконечная температура, перевёрнутая вилка, неположительный коэффициент
  контакта — исключение на старте.
- ⚠ `SkeletonContactFactor` — **калибровочная постоянная, не ручка
  подгонки**. δ входит в модель только через тепловой поток металла, который
  этот коэффициент делит, поэтому значение, подобранное ради качества
  совпадения, алгебраически равно отключению ограничения δ ≤ d_AP — а
  ограничение при этом продолжит печататься выполненным.
- Поверхностная доля каркаса `f_s` — **всегда кривая**
  (`SkeletonCoverageCurve`), а не число, потому что равновесное замыкание
  делает её зависимой от температуры поверхности. Полиномиальное замыкание —
  частный случай постоянной кривой, и именно это оставляет ненастроенные
  запуски бит-в-бит теми же.
- `SkeletonCoverageCurve.At` **интерполирует линейно** внутри выборки и
  **зажимает** значения за её краями, а не экстраполирует.
- `SkeletonCarbonEquilibriumTable.CurveFor` **бросает** для неизвестного
  топлива или давления. Молчаливой интерполяции по давлению нет: таблица,
  не покрывающая загруженный набор, обязана падать на старте.
- Кинетическое замыкание: `f_s = 1 / (1 + a₀ + a₁·w_fine·(p/p_ref)^m)` с
  калиброванными по умолчанию `a₀ = 0.9966`, `a₁ = 3.3653`, `m = 0.71`,
  `p_ref = 1 МПа`. ⚠ Постоянные калиброваны **только на `Bas_2`/`Bas_3`/`Bas_4`**
  и не описывают `Bas_0` и `Bas_1` — у тех другое связующее.
- `MetalCombustionParamsByUnits.MetalMeltingTemperature` и
  `DiffusionFlameParamsByUnits.FinalTemperature` объявлены с `set`, а не
  `init` — единственные изменяемые поля среди входных, и это осознанно:
  решатель правит их в ходе итерации.

## Dependencies

- [Units](../../Units/API.md) — `AMetalBurningConstant`, `BMetalBurningConstant`
  в размерном ярусе вектора параметров;
- [Extensions](../../Extensions/API.md) —
  `PropellantExtensions.MetalMeltingTemperatureKelvins` как значение по
  умолчанию для `ModelConstants`;
- [ProblemContexts](../ProblemContexts/API.md) —
  `SurfaceTemperatureSearchBounds` как значения вилки по умолчанию.
  ⚠ Написано **относительной квалификацией** (`ProblemContexts.…`), а не
  `using`: оба узла лежат под `Models`. Поиск по `using` эту связь не найдёт.

⚠ Отступление от §6. Две последние зависимости **встречные**: `Extensions`
зависит от этого узла по `SkeletonCoverageCurve`, а `ProblemContexts` — по
всему набору входных параметров. То есть в дереве есть два цикла между
соседями. Это факт текущего кода, а не замысел; зафиксирован как расхождение
«как есть / как должно быть» в [корневом BOOT.md](../../../../BOOT.md).

## Constraints

Унаследованы от [Computation](../../BOOT.md). Дополнительно: всё, что меняет
любое вычисленное число, обязано быть достижимо через `ModelConstants` —
только так значение попадает в `run_configuration.resolved.json` и в шапку
отчёта.

## Acceptance criteria

- [x] Замыкание по умолчанию — исторический полином при любой температуре
      поверхности (2026-09-05,
      `SkeletonSurfaceFractionTests.DefaultClosureIsTheHistoricalPolynomialAtEverySurfaceTemperature`).
- [x] Поставляемая равновесная таблица покрывает поставляемый набор топлив
      (2026-09-05, `SkeletonSurfaceFractionTests.TheShippedTableCoversTheShippedPropellantSet`).
- [x] Кривая интерполирует линейно между узлами выборки (2026-09-05,
      `SkeletonSurfaceFractionTests.CoverageInterpolatesLinearlyBetweenSamples`).
- [x] Оба яруса контекста используют настроенное замыкание (2026-09-05,
      `SkeletonSurfaceFractionTests.BothContextTiersUseTheConfiguredClosure`).
- [x] Вилка по умолчанию — историческая 600–900 К, настроенная доходит до
      обоих ярусов, непригодная отвергается (2026-09-05,
      `SurfaceTemperatureBracketTests`).
- [x] Коэффициент контакта по умолчанию не меняет модель и делит поток металла
      одинаково в обоих ярусах (2026-09-05, `SkeletonContactFactorTests`).
- [x] Кинетическое замыкание воспроизводит свой калибровочный набор, остаётся
      долей, плоско по температуре поверхности и различает композиции только
      по тонкому окислителю (2026-09-05, `KineticCoverageTests`).
- [ ] Совпадение раскладки `FromVector` между ярусами машиной не проверяется —
      это самое опасное непокрытое место узла.

## Taboos

- Не делать `f_s` параметром поиска: коэффициент, который оптимизатор мог бы
  двигать, алгебраически тождествен перераспределению между двумя
  предэкспонентами кинетических пламён.
- Не подбирать `SkeletonContactFactor` по качеству совпадения. Выбрать один
  раз по заявленному правилу, заморозить, а любой скан подавать как анализ
  чувствительности.
- Не менять раскладку 32-вектора, не пройдя всех её потребителей.
- Не приводить числа `Bas_0` и `Bas_1`, полученные под кинетическим
  замыканием.
