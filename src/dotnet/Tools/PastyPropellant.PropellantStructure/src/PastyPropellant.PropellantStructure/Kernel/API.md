# API.md — Kernel

✅ **Узел перенесён целиком.** Есть сама модель — все проходы, обе ветви,
накопители, девять условий, пересчёт модели мелкого окислителя; числовая сборка
(строки 770–996 и 1086–1152) и укладка печатных величин (1182–1515, где считаются
только часы). На пробнике из 20 частиц, снятом под wine, порт воспроизводит **все**
печатаемые целые числа точно: `NFX`/`NFY`/`NFZ`/`NFQ`/`NFW`, полное число карманов
и девять счётчиков условий, — и 31 печатный скаляр из 34 совпадает с оракулом
точно, а три оставшихся укладываются в 10⁻⁵ по причине, не зависящей от порта
(см. `../Geometry/BOOT.md`).

✅ **L2 зелёный на шести архивных прогонах** (2026-08-16, 57 мин, 24 теста из 24 —
четыре группы на `rps02`, `rps01`, `hp1`, `hp315`, `r1`, `r2`). На каждом сверены
все четыре группы: пять счётчиков розыгрышей и девять счётчиков условий — **точно**,
все **51** печатный скаляр и все **14** печатных массивов по ячейкам (1394–2255
ячеек на прогон) — с допуском, выведенным из формата печати каждой величины.
`rps01` и `rps02` — единственные два прогона архива, берущие ветку
гомогенизированного окислителя (`fineoxy_fr` = 0.1566 и 0.7064). Масштаб: `nfy`
доходит до 474 312 537 (`hp315`), и совпадает **до единицы** на всех шести.

⚠ **Ни одна из величин не совпадает «почти».** Целые совпадают точно; расходятся
только величины вида `|a − b| / b` при `a ≈ b`, и все их отклонения не превышают
**двух ulp** одинарной точности — то есть разрешения самой арифметики, а не порта.
Поэтому у шести таких скаляров допуск имеет **абсолютный пол** `2⁻²³`: относительный
допуск формата на них требует цифр, которых у величины нет. Разбор — в
`../../../tests/PastyPropellant.PropellantStructure.Tests/API.md`, §«Пол на
сокращении разрядов»; тот же счёт, но на одно сокращение глубже, разобран для
`epsdoksd_n` в [Results/API.md](../Results/API.md).

⚠ Две ошибки порта нашла именно сверка массивов, и обе — про то, как читать
объявления, а не формулы. `ALLDOK` выделен по `Ndok`, а не по числу фракций, хотя
стоит строкой ниже одноимённого `ALLDOK_FRACT`; и доля фракции считается в
**одинарной** точности (явный `REAL()` в числителе, приведение `INTEGER*8` к типу
второго операнда в знаменателе), что при счётчиках порядка 10⁸ квантует результат
заметно для величины, которую он затем измеряет.

Всё `internal`: наружу узел выходит только через `PropellantStructureModel`
уровнем выше — и напрямую доступен тестовой сборке через `InternalsVisibleTo`,
без чего L2 не смог бы запустить прогон.

## Операции

```csharp
internal sealed class StructureSimulation
{
    internal StructureSimulation(
        StructureRunConfiguration configuration,
        RandomStreamSet streams);

    // ✅ Прогон целиком: 1 + KXX проходов (нулевой подготовительный и KXX рабочих;
    // KXX <= 1 нормируется в 1). Отдаёт сырые накопители.
    internal RunState Simulate(
        IProgress<StructureProgress>? progress = null,
        CancellationToken cancellationToken = default);

    internal int TotalPasses { get; }          // 1 + KXX
    internal int BaseParticlesPerPass { get; } // N

    // ✅ Производные величины последнего завершённого прохода; null до первого.
    internal PassSummary? Summary { get; }

    // ✅ Тот же прогон плюс укладка печатных величин под именами отчёта.
    internal StructureResult Run(
        IProgress<StructureProgress>? progress = null,
        CancellationToken cancellationToken = default);
}
```

`RunState` — накопители одного прогона под именами оригинала, с его типами
(`REAL*4` → `float`, `REAL*8` → `double`, `INTEGER*8` → `long`) и индексацией с
единицы. Это не контракт наружу, а то, из чего `Run` собирает `StructureResult`.
Наружу `Simulate` и `RunState` остаются доступны только тестовой сборке: L2 читает
по ним ту группу счётчиков, которую результат не несёт.

⚠ **Печатное значение и хранимое — разные вещи, и путать их нельзя.** Результат
хранит длины в метрах; отчёт печатал микрометры, причём умножая не на `1e6`, а на
`1.00001e6` — поправка против усечения в `int()`. Эта поправка принадлежит печати,
а не длине, и в результат не попадает.

⚠ **Ничего в `RunState` не обнуляется между проходами.** Рабочий проход
продолжает подготовительный, и печатаемые характеристики окислителя набраны по
`(1+KXX)·N` частицам. Это поведение оригинала, а не недосмотр.

Прогресс и отмена проверяются на границе базовой частицы и **не влияют на числа**:
ни один розыгрыш не зависит от того, подписан ли слушатель.
`CancellationToken` проверяется на той же границе. Прерванный прогон не
отдаёт частичного результата: `Run` бросает `OperationCanceledException`. Половина
выборки Монте-Карло — не результат меньшей точности, а результат неизвестной.

## Что кладётся в результат сверх печати оригинала

Оригинал их не печатал, эталона у них нет, и они помечены как непроверенные:

- число начатых реализаций за прогон, `AttemptsTotal`. Полезно оно отношением к
  принятым, `(1+KXX)·N`: сколько реализаций рецептура выбрасывает на одну
  оставленную. ⚠ Тождественно равно `NFX` — каждый приход на метку 11 разыгрывает
  ровно одну базовую частицу, — и это не дублирование, а проверяемое утверждение о
  модели; разбор в `BOOT.md`;
- число зажимов при розыгрыше размера кармана (`Sampling`). ⚠ Его нормальное
  значение — **ноль**: зажим недостижим на реальном розыгрыше, разбор в
  [Sampling/API.md](../Sampling/API.md). Счётчик существует, чтобы отклонение от
  нуля было видно, а не чтобы измерять ожидаемую частоту;
- число случаев NaN на выходе `Geometry` (в 43 эталонных прогонах NaN не
  встречается ни разу — счётчик существует, чтобы это оставалось видно);
- заданное `KXX`, фактическое число проходов после нормировки (`1 + KXX`, из них
  один подготовительный).

⚠ Шесть массивов `*_n` в этот список **не входят**, хотя выглядят как его законные
члены: оригинал их печатает, просто под условием `KXX > 1`, которого нет ни в одном
из 43 архивных прогонов. Их эталон — `probe3.m`, снятый под wine специально; лежат
они в `RunDiagnostics.Convergence`, по строке на рабочий проход, и разбор шести
имён (три разные величины, две со знаком, одна вообще не погрешность) — в
[Results/API.md](../Results/API.md). Пока фикстуры не было, порт их не считал —
и это была не лень, а то же правило: величина без эталона не переносится.

## Гарантии

- детерминизм: одна конфигурация + один набор состояний генератора → один
  результат, бит в бит;
- нет побочных эффектов: ни файлов, ни статики, ни `Console`. Протокол прогона
  пишет `Configuration/`, отчёт — вызывающий;
- нет разделяемого состояния: два экземпляра `StructureSimulation` независимы,
  но **внутри** одного прогона параллелизма нет.

## Не предоставляется

- частичный или потоковый результат по ходу прогона;
- предел числа повторов розыгрыша (см. [BOOT.md](./BOOT.md), «Табу»);
- любой способ «исправить» опечатку строки 529 и тем включить условие 1.
