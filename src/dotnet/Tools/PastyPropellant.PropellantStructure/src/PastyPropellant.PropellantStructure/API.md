# API.md — Библиотека PropellantStructure

Этот узел — сборочный. Его внешний контракт совпадает с контрактом всей сборки и
описан в [корневом API.md](../../API.md).

✅ **`PropellantStructureModel` написан** (2026-08-16). Сборка экспортирует его,
`SizeDistributionLaw` из [Sampling/API.md](./Sampling/API.md), весь публичный
контракт [Configuration/API.md](./Configuration/API.md) — конфигурацию, её
валидацию, чтение из JSON и запись фактического прогона — и весь публичный
контракт [Results/API.md](./Results/API.md). Узлы `Sampling/`, `Geometry/` и
`Kernel/` реализованы целиком и целиком же `internal`.

⚠ **Зерна генератора наружу не выводятся, и это решение, а не упущение.**
Оригинал объявляет шесть литеральных векторов и никогда их не меняет, поэтому
прогон есть чистая функция своей конфигурации — именно это и делает архивный
отчёт эталоном. Параметр «зерно» здесь порождал бы прогоны, которые ни один
архивный отчёт рассудить не может, но выглядят неотличимо от тех, которые может.
Если когда-нибудь понадобятся независимые повторности, им нужен свой вход и своё
имя.

## Что видно снаружи сборки

```csharp
public static class PropellantStructureModel
{
    public static StructureResult Run(StructureRunConfiguration configuration);
    public static StructureResult Run(StructureRunConfiguration configuration,
                                      IProgress<StructureProgress>? progress,
                                      CancellationToken cancellationToken = default);
}

public readonly record struct StructureProgress(
    int Pass,                 // номер прохода, 0..KXX; 0 - подготовительный
    int TotalPasses,          // 1 + KXX после нормировки (KXX <= 1 даёт 1),
                              // то есть 2 во всех 43 эталонных прогонах
    long AcceptedParticles,   // принятых базовых частиц в текущем проходе
    long TargetParticles);
```

⚠ **Исправлено 2026-08-15.** Здесь стояло `Pass` = `1..TotalPasses` и
`TotalPasses` = `KXX`. Так запись не могла назвать проход, с которого прогон
начинается: оригинал делает **`1 + KXX`** проходов — нулевой подготовительный,
строящий гистограмму мелкого окислителя, и `KXX` рабочих. Нумерация с нуля — не
вкус, а то, что печатает сама программа (`Cycle = 0`, строка 422). Разбор — в
[Kernel/BOOT.md](./Kernel/BOOT.md), «Ход одного прогона».

Публичные типы, определённые в дочерних узлах и переэкспортированные отсюда:

- из [Configuration/API.md](./Configuration/API.md) — `StructureRunConfiguration`
  и весь её контракт (валидация, чтение JSON, запись фактического прогона);
- из [Results/API.md](./Results/API.md) — `StructureResult`, `Correction`,
  `Verification`, `Verified<T>`, `Distribution`, `DistributionGrid` (с тремя
  вложенными видами), `DistributionNormalisation`,
  `ConditionalOxidiserByPocketSize`, `RunDiagnostics`, `ConditionCounters`,
  `StructureResultComparison`, `BranchMismatchException`, `PrintedArrays`.

⚠ Поверхность `Results/` шире, чем «результат и перечисление», и это осознанно.
Требование `BOOT.md` «публично только перечисленное в корневом `API.md`» здесь
исполняется тем, что список выше **и есть** перечисление; требование минимальности
уступает инварианту узла: сетку распределения и ветвь поправки нельзя сделать
`internal`, не отняв у вызывающего возможность прочитать результат правильно.

## Что видно соседям внутри сборки

Ничего. `Kernel/`, `Sampling/`, `Geometry/`, `Results/` и `Configuration/` не
обращаются к этому уровню — зависимость односторонняя, сверху вниз.

## Что видно тестовой сборке

Всё. `InternalsVisibleTo("PastyPropellant.PropellantStructure.Tests")` объявлен в
`.csproj`, потому что L0 и L1 проверяют именно внутренние узлы. Это единственный
консумер, кроме самой сборки; никакой другой доступа к `Sampling/`, `Geometry/`
и `Kernel/` не получает.

## Гарантии

- детерминизм: один вход → один выход, всегда;
- `resolved.json` записан до первого розыгрыша;
- исключение конфигурации бросается до начала счёта, а не в середине.

Все три проверяются с 2026-08-16 (`PropellantStructureModelTests`), и первые две
проверяются именно здесь, а не уровнем ниже. Детерминизм сверяется по битам
каждого печатного скаляра, а не только через `Equals`: совпадение до
пятнадцатого знака `Equals` на `double` удовлетворило бы, а утверждение — «те же
числа». Запись `resolved.json` проверяется прогоном, снятым отменой **из
обратного вызова прогресса**, то есть на границе базовой частицы, до которой он
уже дошёл, — иначе «прерванный на середине» проверялся бы прогоном, который не
начинался.

⚠ Отдельно проверено, что фасад прогоняет **то же самое**, что реплеит L2: на
пробниках результат побитово тождествен пути `new StructureSimulation(cfg,
RandomStreamSet.Historical())`, а счётчики `hp1` сверяются через сам фасад.
Без этого зелёный L2 оставался утверждением о ядре: все его тесты передают набор
состояний генератора явно, то есть делают за фасад ровно тот выбор, ради
которого он существует.
