# API.md — Sampling

Всё `internal`, **кроме одного перечисления**. Внутри сборки узел предназначен
только для `Kernel/` — это дисциплина, а не гарантия языка: `internal` виден всей
сборке, а через `InternalsVisibleTo` ещё и тестовой, которая обращается сюда
напрямую (L0 и L1).

Пространство имён — `PastyPropellant.PropellantStructure.Sampling`.

Статус каждого объявления помечен: ✅ реализовано, ⏳ запланировано.

## Закон распределения ✅ — единственный публичный тип узла

```csharp
public enum SizeDistributionLaw { Surface = 1, Volume = 2 }   // JZ оригинала
```

Публичен потому, что это выбор вызывающей стороны, а `Configuration/` его только
переносит. Определён здесь, а не там, чтобы стрелка зависимости шла из
конфигурации в выборку и узел **по-прежнему ни от кого не зависел**.

Закон задаёт сразу обе половины обращения: формулу, которой `SIZE` превращает
розыгрыш в диаметр, и вес, которым `PARAM` превращает массовую долю в числовую, —
потому что второе есть обратный третий момент первого. Разъезд между ними
невозможно поймать никакой фикстурой, и именно его проверяет L1.

## Генератор ✅

```csharp
internal interface IRandomStream
{
    double Next();          // (0,1); один шаг состояния
}

internal sealed class Random2Stream : IRandomStream
{
    internal const int StateWords = 10;

    internal Random2Stream(ReadOnlySpan<int> seed);   // 10 слов, дословно из исходника
    internal int[] State { get; }                     // копия состояния; нужна L0
}

internal sealed class Random1Stream : IRandomStream
{
    internal Random1Stream(float a, float b);         // два слова REAL*4 — всё состояние
    internal static (float A, float B) Origin { get; } // 0.12345678 / 0.87654321, строки 345-346
    internal (float A, float B) State { get; }         // пара, как её пишет AX/BX
}

internal sealed class RandomStreamSet
{
    internal static RandomStreamSet Historical();     // gsv=2: шесть состояний, литеральные затравки
    internal static RandomStreamSet Toy(int warmup);  // gsv=1: шесть срезов одной орбиты через NNZ

    internal IRandomStream BaseFraction      { get; } // X   - состояние 1
    internal IRandomStream BasePosition      { get; } // X0  - состояние 2
    internal IRandomStream Spacing           { get; } // X1  - состояние 3
    internal IRandomStream NeighbourFraction { get; } // X2  - состояние 4
    internal IRandomStream NeighbourPosition { get; } // X21 - состояние 5

    // X3 (размер кармана) и X4 (обе монетки) - ОДИН объект, не два
    internal IRandomStream PocketAndCorrections { get; } // состояние 6

    // литеральные затравки строк 52-63; отдельный тип, потому что L0 проверяет
    // соотношения между самими затравками, а не только между потоками
    internal static class Seeds
    {
        internal static ReadOnlySpan<int> State1 { get; }  // ... State6
    }
}
```

⚠ **Счётчики розыгрышей и суммы `XSS*` живут в ядре, а не здесь.** Оригинал
увеличивает `NFX`/`NFY`/`NFZ`/`NFQ`/`NFW` и накапливает суммы **на месте вызова**
(строки 463, 498, 518, 622, 662, 698), причём шестое состояние обслуживают **два
разных** счётчика: `NFQ` считает розыгрыши `X3` (622), `NFW` — розыгрыши `X4`
(662 и 698). Один счётчик на потоке не смог бы воспроизвести оба. Поэтому у
`IRandomStream` нет ни `DrawCount`, ни статистики: поток умеет ровно один шаг.

⚠ Состояния — не независимые потоки. Состояние `k` есть состояние `k−1`,
сдвинутое на один розыгрыш; следовательно `BasePosition.Next()` возвращает
предыдущее значение `BaseFraction`. Подробности и почему это обязательно —
в [BOOT.md](./BOOT.md).

⚠ **`Toy` появился 2026-08-16, и появился из-за дефекта.** До этого ядро звало
`Historical()` безусловно, и прогон, попросивший `gsv = 1`, молча получал числа
`gsv = 2`, тогда как разрешённая запись честно фиксировала просьбу. Поймать это
было нечем: выхода `gsv = 1` не существовало ни одного. Теперь он есть
(`reference/propstruct/probes/probe4.m`), и ветка закрыта фикстурой.

`Toy(warmup)` повторяет разметку оригинала буквально: пара пишется на смещениях
0, NNZ, …, 5·NNZ, а присваивается **задом наперёд** (`A6 = AX(1)` … `A1 = AX(6)`),
поэтому долю базовой частицы разыгрывает самое продвинутое состояние, а размер
кармана — сырая затравка. Прогулка в 5·NNZ шагов делается один раз, при
построении.

⚠ **Выбор между `Historical()` и `Toy()` делается не здесь.** `GeneratorSelection`
живёт в `Configuration/`, а этот узел не зависит ни от кого — по той же причине,
по которой `SizeDistributionLaw` объявлен здесь, а не там. Переключатель стоит в
фасаде `PropellantStructureModel`, он же отказывает `SystemSeeded` (`gsv = 3`):
оригинал сеет его извне себя (строка 409) и сам такой прогон не воспроизводит.
Порту такого прогона не с чем сверяться — включая сам оригинал.

## Обращение распределения фракций ✅ — `PARAM` + `SIZE`

```csharp
internal sealed class FractionSampler
{
    internal static FractionSampler Build(
        SizeDistributionLaw law,
        ReadOnlySpan<float> massFractions,     // G, по одной на фракцию
        ReadOnlySpan<float> bounds,            // DOK, 2*N границ, метры
        ref double statisticalSignificance,    // alfa: МУТИРУЕТСЯ, как в оригинале
        out float maximumSize);                // Dmax; оригинал перезаписывает его
                                               // вызовом SIZE (строка 1754)

    internal int FractionCount { get; }                    // NM
    internal ReadOnlySpan<double> Probabilities { get; }   // ZX, нормированные числовые доли
    internal ReadOnlySpan<double> Cumulative    { get; }   // Z11, N+1 узлов от 0 до 1
    internal float ProbabilitySum { get; }                 // ZSS, ненормированная сумма весов

    internal float Diameter(double x, double x1, ref int fractionIndex);
}
```

Почему именно такие типы:

- **`float`, а не `double`, на входе и выходе.** `G`, `DOK` и `Dr` объявлены
  `REAL*4`; хранить их в `double` — это уже другая модель. `Z` и `Z1` объявлены
  `REAL*8` и потому `double`.
- **`ref int fractionIndex`, а не `out`.** `SIZE` не инициализирует свой выходной
  индекс и не пишет в него, когда розыгрыш не попал ни в один интервал. Значит,
  устаревшее значение принадлежит **переменной вызывающего**: два места вызова в
  главной программе делят одну (строки 460 и 515), а `PARAM` держит свою (1754).
  `out` стёр бы это различие.
- `ProbabilitySum` отдаётся наружу, потому что `ZSS` уходит в масштаб удельной
  поверхности (строка 378), а не является деталью нормировки.

⚠ Мутация `alfa` реальна (строка 1750), но происходит **только** в ветке
`(x − z1(Imax)) < 0`, недостижимой при `alfa = 0` — то есть во всех 43 эталонных
прогонах. Сигнатура выносит наружу поведение, у которого нет ни одного эталонного
прогона; помечать его проверенным нельзя.

⚠ `ZS` объявлен `REAL*4`, тогда как веса, которые он суммирует, — `REAL*8`.
Поэтому `Probabilities` **не даёт в сумме единицу** в двойной точности: промах
порядка машинного эпсилона одинарной точности (для `hp1` — 5.4·10⁻⁸). Верхний
узел `Cumulative` равен единице не потому, что так сошлось, а потому что строка
**1732** присваивает её принудительно; `Zerror` на строке 1733 измеряет этот
промах и выбрасывает его. Пин несущий, а не косметический.

`Zerror` в порт не транскрибируется — по общему правилу дерева о мёртвых
присваиваниях, см. [../BOOT.md](../BOOT.md).

## Розыгрыш размера кармана ✅ — построение таблицы + `DM`

```csharp
internal sealed class PocketSizeSampler
{
    internal PocketSizeSampler(int capacity);   // Nkarm

    // Строки 587-610: сворачивает окно гистограммы карманов в табулированную
    // обратную функцию. false = в окне нет массы (AUS = 0), это GO TO 11
    // оригинала: вызывающий бросает базовую частицу.
    internal bool Rebuild(ReadOnlySpan<float> histogram,  // QKS1, индексация с 1
                          int firstBin,                   // mindk
                          int lastBin,                    // maxdk
                          float binWidth);                // Di, метры

    internal float Draw(double x);              // DM, строки 1573-1586

    internal int  Capacity  { get; }            // Nkarm
    internal int  NodeCount { get; }            // NNN1
    internal long ClampCount { get; }           // ожидается 0 — см. ниже
    internal ReadOnlySpan<float> Cumulative { get; }
    internal ReadOnlySpan<float> Diameters  { get; }
}
```

Построение таблицы живёт здесь, а не у вызывающего, потому что сворачивается
**распределение**. У вызывающего остаётся арифметика, выбирающая окно
(`AK3·Dr`, `AK4·Dr`), — это геометрия, а не выборка.

⚠ **Смещение на один разряд.** Узел `i` таблицы стоит в `Di·разряд`, то есть на
**верхней** границе того разряда, чья масса заполняет интервал над ним, тогда как
карманы раскладывались по разрядам как `int(RK/Di)+1`, то есть в
`[(разряд−1)·Di, разряд·Di)`. Переразыгранные диаметры карманов систематически на
один разряд крупнее тех, из которых таблица построена. Дефект модели,
воспроизводится; закреплён тестом, чтобы его не «прибрали».

⚠ **`ClampCount` обязан оставаться нулём, и это проверено.** Прежняя редакция
этого документа утверждала, что `DM` выходит за конец массива примерно 0.4 раза
за прогон, когда накопленная в одинарной точности сумма останавливается на
0.99999994. Это неверно: усечение строк 600–605 срабатывает на **первом** узле,
подошедшем к единице ближе 10⁻⁵, и присваивает ему ровно единицу, а 0.99999994
отстоит от единицы на 6·10⁻⁸ — на шесть порядков внутри порога. Чтобы таблица
действительно не дотянула, накопленная ошибка округления должна достичь 10⁻⁵, а
она не может: приращение, слишком малое, чтобы сдвинуть кумуляту, с точностью до
одной двоичной октавы совпадает с приращением, слишком малым, чтобы сдвинуть
нормирующую сумму `AUS`, — обе ошибки гасят друг друга по построению. Перебор
300 000 случайных гистограмм на 20…2400 разрядов дал худший недобор 6.7·10⁻⁶ и
растёт лишь как корень из числа разрядов.

Зажим остаётся не как воспроизведение наблюдаемого поведения, а как страховка:
`Draw` в C# обязан быть тотальным там, где оригинал читает соседнюю память, а
счётчик нужен, чтобы срабатывание было **видно**, а не выглядело правдоподобным
числом. Ненулевой `ClampCount` — сигнал, а не норма.

## Гарантии

- детерминизм при одинаковых затравках и одинаковой последовательности вызовов;
- `Draw` не бросает при выходе за конец таблицы: зажимает и считает;
- массивы внутри узла индексируются **с единицы**, как в Фортране; нулевой
  элемент существует и не используется. Это позволяет читать индексные выражения
  прямо из исходника.

## Где узел бросает, а оригинал — нет

Три места, и во всех оригинал не «работает иначе», а имеет **неопределённое
поведение**: зацикливается или читает чужую память. Порт отказывается громко,
потому что тихо воспроизвести нечего.

| Место | Что делает оригинал | Что делает порт |
|---|---|---|
| `Build`, скан `Dmax` не выбрал ни одной фракции | `Imax` остаётся от прошлой итерации, цикл `1055` крутится вечно | `InvalidOperationException` |
| `Diameter`, индекс фракции вне `1..NM` | читает `DOK` за границей массива | `InvalidOperationException` |
| `Draw` до успешного `Rebuild` | таблица из нулей, интерполяция по мусору | `InvalidOperationException` |

Плюс `Rebuild` бросает `ArgumentOutOfRangeException` на окне, которое не помещается
в гистограмму: в оригинале такого окна возникнуть не может (`maxdk ≤ Nkarm` по
построению `Nkarm`), поэтому проверка ловит ошибку вызывающего, а не ветку модели.

Ни один из четырёх случаев не достижим при историческом входе. Первые два требуют
`alfa` больше числовой доли самой широкой фракции, третий — нарушения протокола
«`Rebuild` вернул `false` — базовая частица бросается», четвёртый — ошибки в
арифметике окна. Отказ здесь — это диагностика для `Kernel/`, а не поведение
модели.

## Не реализовано намеренно

`GeneratorSelection.Toy` (`random1`) и `SystemSeeded` (`drand`) — эталона нет.
Обращение к ним бросает `NotSupportedException`. ⏳ Отказ появится вместе с
`Configuration/`; сейчас этих типов ещё нет, и единственный способ получить
поток — `RandomStreamSet.Historical()`.
