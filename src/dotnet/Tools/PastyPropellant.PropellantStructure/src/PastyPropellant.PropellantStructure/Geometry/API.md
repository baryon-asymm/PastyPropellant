# API.md — Geometry

Всё `internal`. Внутри сборки узел предназначен **только** для `Kernel/` — это
дисциплина, а не гарантия языка: через `InternalsVisibleTo` сюда обращается ещё и
тестовая сборка, на которой держится L1.

Пространство имён — `PastyPropellant.PropellantStructure.Geometry`.

## Операции ✅

```csharp
internal enum BridgeOutcome
{
    Built,              // JJ = 1
    GapExceedsPocket,   // строка 1597, A >= 2*RK, до всякого счёта
    WidthNegative,      // строка 1612, BB < 0, после вычисления ширины
}

internal static class BridgeVolume
{
    /// <summary>Объём межкарманной перемычки (VM оригинала, строки 1588–1629).</summary>
    /// <param name="radiusA">радиус первой частицы, м (R1)</param>
    /// <param name="radiusB">радиус второй частицы, м (R2)</param>
    /// <param name="pocketRadius">радиус посаженного кармана, м (RK)</param>
    /// <param name="gap">зазор между частицами, м (A)</param>
    /// <param name="volume">объём, м³ (VMKM); NaN, если исход не Built</param>
    /// <param name="width">ширина перемычки (BB); NaN, если подпрограмма вышла до её вычисления</param>
    internal static BridgeOutcome Between(
        float radiusA,
        float radiusB,
        float pocketRadius,
        float gap,
        out float volume,
        out float width);
}
```

Единственный вызов оригинала — строка 624:
`CALL VM(Dr/2., Db/2., DKARM/2., AA, JJ, VMKM, BB)`. Радиусов **три**: две
частицы и карман между ними; зазор — четвёртый аргумент.

Аргументы передаются **по значению**: подпрограмма упорядочивает радиусы у себя и
не должна иметь возможности изменить состояние вызывающего.

Все величины — `float`. В оригинале и формальные аргументы, и все промежуточные
переменные `VM` — `REAL*4` по неявной типизации, поэтому **каждое присваивание
округляет**, а не только последнее. Правая часть при этом считается в `double`.

## Что это за тело

Тело вращения вокруг линии центров. Луч из центра каждой частицы к центру кармана
пересекает её поверхность по окружности; тело ограничено плоскостями этих двух
окружностей, сбоку — конусом через них, и уменьшено на два шаровых сегмента,
которыми частицы в него вдаются.

`VM` — **точная замкнутая форма** этого тела, а не приближение к нему. Тождество

```
(R1A − R2A)·tan(AL + (π − AL − DE)/2) = AC − Q1 − Q2
```

выполняется с машинной точностью (проверено на восьми конфигурациях, невязка
10⁻¹³…10⁻¹⁶ относительных), то есть конус, который формула строит из углов
треугольника, и есть конус через обе окружности. Численное интегрирование тела
совпадает с замкнутой формой на пяти значащих цифрах.

## Два независимых исхода «не построена»

| Условие | Строка | Смысл |
|---|---|---|
| `gap ≥ 2·pocketRadius` | 1597 | карман не помещается в зазор |
| `width < 0` | 1612 | перемычка вырождена |

Оба дают отказ и **разные** причины; счётчик в результате ведётся по каждой
отдельно. Первое условие заодно гарантирует, что треугольник на трёх центрах
замыкается: `AB + BC ≥ AC` сводится ровно к `2·RK ≥ A`.

При отказе оригинал возвращается, оставив у вызывающего прежние `VMKM` и `BB`, а
вызывающий их не читает. Порт вместо этого отдаёт `NaN`, чтобы чтение было
громким, а не правдоподобным. `WidthNegative` — исключение: ширина к этому моменту
вычислена, и она возвращается.

## Гарантии

- чистая функция без состояния и без побочных эффектов;
- π внутри равно `3.14` — и это **не масштабная поправка**, см. [BOOT.md](./BOOT.md);
- исключения не бросаются, включая NaN на входе арккосинуса и NaN во входных
  аргументах;
- порядок аргументов не важен: `Between(a, b, …) == Between(b, a, …)`.

Чего в этом списке **нет**: побитового совпадения с оригиналом. `ACOS`/`SIN`/`TAN`
берутся из другой библиотеки, чем у Compaq, и на пограничной конфигурации это
способно перевернуть знак `width` — то есть исход. Разбор в [BOOT.md](./BOOT.md).

## Не предоставляется

Невязка строки 1611 (`error = BB-2*(BC*SIN(DE)-RK)`) — расхождение двух способов
посчитать **ширину**. Оригинал её вычисляет и отбрасывает; она не читается нигде
и не наблюдаема ни в одном выходе, поэтому в порт **не транскрибируется** по
общему правилу поддерева о мёртвых присваиваниях ([../BOOT.md](../BOOT.md)).
Второй такой случай — `Zerror` в `PARAM`; уникальным этот не является.
